Connect to your DeepSQL server

DeepSQL runs on your own VM or hardware. Point this client at it over TLS, or tunnel in over SSH when the ports are closed to the internet.

How this client reaches the VM

Server

CA bundle
Certificates are not verified until the first one is pinned. Anyone who can intercept this network can read the session. Use it to bootstrap, then switch to Pinned certificate.

SSH

Private key
Uses the key already loaded in your SSH agent (SSH_AUTH_SOCK, or Pageant on Windows). Nothing is stored by this app.

Forwarding

Forwards to DeepSQL as seen from inside the VM. Use 3000, the frontend container — a host reverse proxy on port 80 usually matches on hostname and will answer a tunnel with 404, because the tunnel's Host header is 127.0.0.1. Local port 0 picks a free port and reuses it next time.
